# DGF-Bench website

The public website of [DGF-Bench](https://github.com/jeremy1392/DGF-Bench), served by GitHub Pages at
**https://dgfbench.com**. DGF-Bench is an open-source, defensive-security benchmark for tool-using LLM agents
acting as enterprise governance reviewers: a board of agents reviews synthetic project dossiers, an attacker
plants deceptive content in evidence the organization does not vouch for, and the benchmark measures which
attacks get through (DGF score = 100 × attacks blocked / attacks applicable).

The site is plain static HTML, CSS and JavaScript: no build step, no framework, and no external requests
(no CDN, web fonts or analytics). The one exception is the Ko-fi support button, a floating widget
loaded on every page from `storage.ko-fi.com` (page `dgfbench`). Every page also works when opened
directly from disk.

## Structure

| Path | Contents |
|---|---|
| `index.html` | home: the "Frontier Labs DGF-Bench Results" leaderboard, why DGF-Bench is essential, key findings, how it works, built for AI labs, who it is for, put your model on the leaderboard, help us |
| `benchmark.html` | how the benchmark works: dossiers, routes and gates, the board, tools, information conditions, scoring |
| `attacks.html` | the 29 attacks: threat model, the four families, one card per attack with its results |
| `results.html` | the September 2026 results: leaderboard, score bars, attack × model matrix, findings, outcome-strict under attack, corrections, downloads |
| `get-started.html` | install, first run, outputs, reading the report, submitting a score (`#submit`), other commands |
| `about.html` | what DGF-Bench is, creator (`#creator`), contact, citation, license, releases, responsible use |
| `help.html` | "Help us": support for rating more models (Ko-fi, https://ko-fi.com/dgfbench) and other ways to help |
| `404.html` | page served by GitHub Pages for any missing path (uses root-absolute links, `noindex`) |
| `assets/css/site.css` | design system and component library (tokens: dark default, light theme; print styles) |
| `assets/css/marketing.css` | home page only (`index.html`) |
| `assets/css/benchmark.css`, `attacks.css`, `results.css`, `help.css` | styles of the page of the same name |
| `assets/css/guide.css` | `get-started.html` and `about.html` |
| `assets/js/site.js` | theme toggle, mobile menu, copy buttons, heading anchors, current-page marker in the nav |
| `assets/js/charts.js` | leaderboard (with the "Add your latest model here" slot), score bars, attack × model heatmap, clean-vs-attack table, rendered from `window.DGF_DATA` |
| `assets/js/attacks.js` | `attacks.html` only: the result rows of each attack card, from `window.DGF_DATA` |
| `assets/img/` | logo, favicon (`favicon.svg`, `favicon-32.png`, `apple-touch-icon.png`), Open Graph image (`og.svg` and its render `og.png`) |
| `data/results.json`, `data/results.js` | site data generated by `tools/build_data.py` (`results.js` sets `window.DGF_DATA`) |
| `tools/build_data.py` | rebuilds the data from the DGF-Bench results, checks every published number, and refreshes the static blocks of `index.html` and `results.html` |
| `tools/build_og.py` | renders `og.png`, `favicon-32.png` and `apple-touch-icon.png` in `assets/img/` |
| `tools/page_template.html` | skeleton to copy for a new page (head, header, footer, scripts) |
| `CNAME`, `.nojekyll`, `robots.txt`, `sitemap.xml` | GitHub Pages and crawler files |

GitHub Pages publishes every file of the repository, `tools/` included. `robots.txt` keeps `/tools/` out of
search engines, and the template carries a `noindex` line (delete it in a page made from the template).

## Preview locally

```bash
python -m http.server 8000
# then open http://localhost:8000/
```

Opening `index.html` directly from disk also works.

**Theme.** The site is dark by default for every first visit, whatever the system setting, and even with
JavaScript off: every page has `data-theme="dark"` on `<html>` and the dark colors are the `:root` tokens of
`site.css`. The toggle in the header switches to light and stores the choice in the browser (`localStorage`,
key `dgf-theme`). Add `?theme=light` or `?theme=dark` to any URL to force a theme for that view (not stored).
Printing always uses the light palette.

## Rebuild the data

The numbers come from the September 2026 results file of the DGF-Bench repository (`results/*_2026-09.json`).
With a checkout of DGF-Bench next to this folder (`../DGF-Bench`):

```bash
python tools/build_data.py                      # or: python tools/build_data.py path/to/results.json
```

The script (standard library only) writes `data/results.json` and `data/results.js`, recomputes each model's
DGF score with the rule of `dgf_bench.report` and `assets/results/build_charts.py`, and stops if a published
number does not match. It then refreshes the static HTML that pages show when JavaScript is off (charts.js
replaces it when JavaScript runs):

- `index.html`: the leaderboard between the `DGF:leaderboard` markers;
- `results.html`: every block between `<!-- GEN:<name> -->` and `<!-- /GEN:<name> -->` (leaderboard,
  models-table, score-table, heatmap-fallback, totals-table, cva-fallback, noopen-table).

Only the text between the markers changes, and the static leaderboards take their heading level and link
from their host section (`data-heading-level`, `data-link`), as `charts.js` does. Change these blocks in
`tools/build_data.py`, never by hand in the HTML: the next rebuild overwrites them.

Some numbers are written as plain text in the pages and are **not** regenerated: the stat strips and prose of
`index.html`, `results.html` and `attacks.html`, the "Rated so far" card and findings of `help.html`, and the
no-JavaScript fallbacks of `attacks.html`. After a data change, search the pages for the old numbers.

After a change to `assets/img/og.svg` or `assets/img/favicon.svg`, run `python tools/build_og.py`
(needs `cairosvg` and the native Cairo library).

## Before publishing

- **Ko-fi**: the support links point to https://ko-fi.com/dgfbench, and every page loads the Ko-fi floating
  button (script from `storage.ko-fi.com`, just before `</body>`; the page template has it too).
  Nothing is left to replace.

## Publish on GitHub Pages

0. **Make the repository public** (Settings > General > Danger Zone > Change visibility). On a GitHub Free
   plan, Pages can only publish public repositories; a private repository needs GitHub Pro, Team or Enterprise.
1. Push this folder to the `main` branch of `https://github.com/jeremy1392/DGF-Bench-Website`.
2. In the repository: **Settings > Pages > Build and deployment**: Source **Deploy from a branch**, branch
   **main**, folder **/ (root)**.
3. **Custom domain**: `dgfbench.com` (the `CNAME` file already contains it).
4. DNS at the registrar of `dgfbench.com`:

   | Type | Name | Value |
   |---|---|---|
   | A | `@` | `185.199.108.153` |
   | A | `@` | `185.199.109.153` |
   | A | `@` | `185.199.110.153` |
   | A | `@` | `185.199.111.153` |
   | AAAA | `@` | `2606:50c0:8000::153` |
   | AAAA | `@` | `2606:50c0:8001::153` |
   | AAAA | `@` | `2606:50c0:8002::153` |
   | AAAA | `@` | `2606:50c0:8003::153` |
   | CNAME | `www` | `jeremy1392.github.io` |

5. When the DNS check passes, tick **Enforce HTTPS** in Settings > Pages.

`.nojekyll` tells GitHub Pages to serve the files as they are, without a Jekyll build.
